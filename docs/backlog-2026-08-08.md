# Backlog — user directions (2026-08-08)

Direct instructions from Ars. Each item is a requirement; do not treat as
optional. Guidance, not history.

## Policy: frictionless by default

- No confirmation gates except MAYBE messages and email. Everything else
  must feel frictionless (media.play included).
- Confirmation UX (when one exists): a popup INSIDE the chat, or open the
  mic and ask for voice confirmation. Never a silent pending gate where
  the model says "done" while the action waits.

## UI / state panel

- The state panel must be MINIMAL — not a header.
- Place it where the user's eyes naturally land: always in the chat, or
  below/side of the main panel.

## Diagnostics (backend)

- "Pon un video" → agent claimed playing, nothing played. Requirement:
  media.play either plays for real or reports honest failure. No claimed
  success without actual playback.
- "Abre un documento" → first ask produced only text, no open; second ask
  worked. Requirement: document.open acts on the FIRST request.
  ToolCallStore must record every execution (running/done/error/rejected/
  pending) so model behavior is verifiable.
- "Reproducción en espera" after session reset. Requirement: media player
  state must be part of the snapshot (track C) so the player state is
  authoritative across restarts.

## Exit / home affordance

- Requirement: a persistent home affordance. ARS·VOX logo (or home icon)
  in the header = back to mic hero, always the same place.
- Requirement: close (X) on every panel header.
- Requirement: prompt guidance so the agent restores the hero when the
  user signals leaving.
- DETENER stops what is happening — never "go home".
- Do not rely on page refresh as the exit path (it only works while media
  state is NOT in the snapshot).

## Media player

- The progress bar must reflect the REAL YouTube iframe playback position
  (it currently does not).
- Real YouTube search: media.search_youtube currently returns FIXTURES
  only. Implement a real backend — scrape
  https://www.youtube.com/results?search_query=<q> (ytInitialData JSON in
  the page HTML), or a public YouTube API if a key becomes acceptable.

## Analytics / personalization

- SPIKE: logging of user queries to derive personalized behavior — what
  to log, where it lives (local SQLite), retention, and how the agent
  consumes it.

## Agent prompt

- system.md must teach the NATIVE adaptive vocabulary (templates/roles/
  proportions) — the old four-template vocabulary is gone.
- Rule set matches the frictionless policy: only Telegram asks for
  confirmation.
- No news in the panel list.
